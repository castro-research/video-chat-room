# Kurz Server: roadmap de planos

Spec: `docs/superpowers/specs/2026-11-01-kurz-server-design.md`. Cada plano entrega software que roda e tem testes. Escreva o plano N+1 só depois que o N estiver mergeado, para ele partir do código real.

| # | Plano | Entrega | Requisitos do spec | Status |
|---|---|---|---|---|
| 1 | Fundação + identidade | Módulo Go, config, Postgres + migrações, snowflake, registro/login/refresh/logout, `/v1/me`, `/.well-known/kurz`, `/healthz` | RF1, RF2, RNF11, RNF15 (parcial), RNF16 (parcial) | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 2 | Guilds, permissões, canais | `permissions` (puro), guilds, membros, convites, bans, papéis, canais, overrides. Contrato `openapi.yaml` v0.2 | RF3 a RF10, RNF12 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 3 | Mensagens | Enviar, listar por cursor, editar, excluir, reply, reações, read state | RF11 a RF13, RNF4 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 4 | Outbox, bus e gateway | `bus` Postgres (outbox + `LISTEN/NOTIFY`), gateway WebSocket com `seq`, resume, backpressure, cache de permissões | RF16, RNF1, RNF5 a RNF9 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 5 | Anexos e busca | MinIO com URL pré-assinada, FTS com `tsvector`, worker de jobs | RF14, RF15, RNF3, RNF13 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 6 | Voz | Módulo `voice`, token do SFU, `voice.state` | RF17 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |
| 7 | K8s, observabilidade, carga | `deploy/k8s` + kind, métricas Prometheus, OpenTelemetry, rate limit, `loadtest` com bots | RNF8, RNF10, RNF14, RNF15, RNF16 | Concluído (PR: [#3](https://github.com/castro-research/video-chat-room/pull/3)) |

Fora do roadmap: adaptar o cliente Apple ao contrato v0.2 (sub-projeto próprio).

Nota: o `User` do contrato 0.1 tem `role` (papel na comunidade única). No modelo multi-guild o papel é por guild, então o Plano 1 devolve `User` sem `role`, e o contrato v0.2 do Plano 2 formaliza isso.
